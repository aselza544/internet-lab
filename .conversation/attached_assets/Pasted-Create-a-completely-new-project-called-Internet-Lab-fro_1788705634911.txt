Create a completely new project called **Internet Lab** from scratch.

Important:

* This is a brand-new project.
* Do not import, reuse, or assume any previous project or code.
* Do not create a second project.
* Build the actual foundation, not a mockup or a static demo.

## Main Goal

Internet Lab is a secure web gateway platform.

The main user experience we are building toward is:

User opens Internet Lab
→ creates a private session
→ enters a public website URL
→ Internet Lab securely fetches the website through its server-side gateway
→ the result is displayed inside the Internet Lab workspace.

The user's device must NOT act as the Internet Gateway.

The architecture should be designed so that later we can deploy the gateway on a cloud server.

### SSRF protection

Implement defense-in-depth SSRF protection.

Do NOT rely only on a domain blacklist.

Block:

* localhost
* 127.0.0.0/8
* 0.0.0.0/8
* ::1
* private IPv4 ranges (RFC1918)
* link-local addresses
* loopback IPv6
* IPv6 unique-local/private ranges
* multicast/reserved addresses
* 169.254.169.254
* cloud metadata endpoints
* internal network destinations

Resolve DNS and validate the resolved IP address before making the request.

Protect against DNS rebinding.

Redirects must also be validated.

Never allow a safe public URL to redirect to an internal/private address.

Prefer disabling automatic redirects and handling redirects manually with a strict maximum redirect count.

### Request restrictions

For the initial gateway:

* allow GET/HEAD only
* timeout requests
* limit response size
* limit redirects
* do not forward arbitrary user request headers
* do not forward cookies
* do not forward Authorization headers
* do not store request bodies
* do not log credentials or sensitive information

Return safe metadata such as:

* URL
* protocol
* hostname
* status code
* response time
* content type
* response size

## Protected Services

Create a configurable Policy Engine.

Do not hard-code all security rules inside the frontend.

Create a backend security policy layer that can later be updated.

For the first version, explicitly block:

* WhatsApp
* banking/payment portals
* identity verification services
* services designed to collect highly sensitive personal information

If a blocked service is requested, return a safe policy response.

For WhatsApp display:

"هذا الموقع غير متاح داخل Internet Lab لحماية خصوصية المستخدمين ومنع جمع البيانات الحساسة."

Do not attempt to bypass WhatsApp security.

Do not scrape WhatsApp.

Do not collect phone numbers.

Do not collect passwords, OTPs, authentication tokens, payment-card numbers, CVV, bank-account information, or identity-document information.

## Security Requirements

This must NEVER become an open proxy.

The gateway must be:

Authenticated
Rate Limited
SSRF Protected
Policy Controlled
Safely Logged
Isolated where appropriate

A random unauthenticated user must not be able to use the server to send arbitrary requests to arbitrary internal or external destinations.

## Important Browser/Web Rendering Requirement

The long-term goal is not merely to display JSON metadata.

The eventual Web workspace must allow the user to enter a public website URL and view the fetched public website through Internet Lab.

For this first implementation, build the secure gateway foundation and a safe response/content preview.

Do NOT create an insecure unrestricted HTML proxy.

Do NOT execute arbitrary third-party page scripts inside the main Internet Lab origin.

Design the architecture so a later phase can implement a properly isolated website rendering/resource proxy.
